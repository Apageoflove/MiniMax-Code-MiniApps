# MCP OAuth 令牌台

简体中文 | [English](README.md)

给需要 OAuth 的 MCP 服务器完成登录：跑设备码流程（或授权码 + PKCE），令牌全程不进页面，把 `Authorization` 头写进 MiniMax Code 的 MCP 配置，并可以在到期前续期。

作者：[Microbiosis](https://github.com/Microbiosis) · 版本：`1.0.0`

## 安装与使用

把整个目录复制到 MiniMax Code 的数据目录下 `plugins/`。`<dataDir>` 默认是 `~/.minimax`，因此默认安装路径是：

```text
<dataDir>/plugins/mcp-oauth-console/
```

保留隐藏的 `.minimax-plugin/` 目录。重启 MiniMax Code，确认插件已被识别，然后从插件列表打开「MCP OAuth 令牌台」，或直接让助手打开它。

页面会列出 MiniMax Code 配置里的每一个 MCP 服务器，并为每一行显示**两件互相独立的事**：**服务端要求什么**（向端点探测得到）和**本机持有什么**（本地配置里的凭证）。一个服务器可能要求 OAuth、同时又被本地令牌满足；也可能不需要 OAuth、却并没有配令牌。分开显示，两者都不会互相遮蔽。

| 操作 | 行为 |
|---|---|
| 检测 | 按服务端声明的传输方式重新探测，结果显示在**该服务器自己那一行** |
| 授权登录 | 为该服务器完成一次 OAuth 登录，然后弹出确认框，明确告诉你将改动哪个文件的哪个字段 |
| 确认写入 | 改写 `mcp.json` 里 `mcpServers.<name>.headers.Authorization`，先备份，再用真实的 MCP 握手验活 |
| 刷新令牌 | 用已存的 refresh_token 换新 access_token 并写回 |
| 刷新即将过期 | 刷新所有距过期不足 30 分钟的令牌。这是手动操作，**不受自动续期开关影响**，一定会执行 |

## 登录方式

页面提供两种方式，并默认推荐第一种。

**设备码（推荐）**。服务端向授权服务器申请一串短设备码，页面把它和验证页链接一起显示出来；你在授权页确认后，服务端轮询令牌端点直到拿到授权。**全程没有跳转**，因此不依赖浏览器能不能回到本 App。

**授权码 + PKCE**。浏览器打开同意页，授权服务器再跳回本 App 的回环端口。**从 MiniMax Code 3.1.2 起，宿主会对该端口的每个请求做鉴权**，于是回调页会返回 `401`、你的处理器根本不会被执行；但地址栏里仍然带着授权码，把整段 URL 复制回页面即可完成——回调页本身并不需要打开。

两种方式都要求 `state` 精确匹配。而且**登录成功并不会立刻写文件**：页面先给出确认，只有确认之后才落盘。

## 设置

设置面板里有两个开关，以及写入时会碰到的那个文件路径。

| 设置 | 默认 | 作用 |
|---|---|---|
| 到期前自动续期 | 关 | Mini App 运行期间，落在 30 分钟窗口内的令牌会被后台刷新。默认关闭，插件不会自作主张地去联系授权服务器。 |
| 允许内网地址 | 关 | 允许**你自己配置的 MCP 端点**使用回环地址、RFC 1918、运营商级 NAT、链路本地与唯一本地地址。这个开关**不适用于**远程服务器返回的 URL——那些一律按最严格的标准检查。 |

面板里显示的配置路径就是写入真正会碰到的那个文件。它只解析一次，符号链接会被解析成真实路径；如果写入前路径变了，写入会被拒绝。

## 探测是怎么做的

探针使用服务端在配置里声明的传输方式：

- `streamable-http`：发真实的 `initialize` JSON-RPC 调用。
- `sse`：发一个 `GET` 开事件流。对 `/sse` 发 POST 不是该传输的合法调用，只会得到 `405`。

**单凭一个 401 不等于 OAuth。** 只有 `WWW-Authenticate: Bearer resource_metadata="…"` 才被当作 OAuth 声明——这是 MCP 服务器指向自己授权服务器的方式（RFC 9728）。所以页面区分：

| 结论 | 含义 |
|---|---|
| 需要 OAuth | 401 + 可发现的授权服务器，可以跑浏览器流程 |
| 需要 Bearer 凭证 | 401 + Bearer challenge，但没有 `resource_metadata`，找不到授权服务器 |
| 需要凭证·方式未声明 | 401 且没有可用的 challenge。端点要的是**某种**凭证（例如 API key），不一定是 OAuth |
| 未要求 OAuth | 未认证的握手被接受了 |
| 不确定 | 端点返回了别的东西（404、405、5xx），或根本连不上 |

服务端没有声明 OAuth 时，页面不会提供浏览器授权流程——没有授权服务器可供对着跑，此时只能手工配置请求头。

## 数据与访问

### 读取的文件

| 文件 | 用途 |
|---|---|
| MiniMax Code 的 MCP 服务器配置（`mcp.json`） | 要检查的服务器列表，以及要写入的请求头 |

`mcp.json` 是宿主文件，插件没有受支持的 API 访问它。本插件只找两个地方：

1. 宿主自己的数据目录链——从 `context.dataDir` 向上找（插件的数据目录就在 MiniMax 数据目录里面），取遇到的第一个 `mcp.json`；
2. 文档写明的默认位置 `~/.minimax/mcp.json`。

进程工作目录和 Node 可执行文件所在目录**刻意不查**，所以旁边恰好存在的无关 `mcp.json` 不可能抢到。向上查找**到 MiniMax 数据目录为止**，也不会再伸到用户主目录，所以主目录里一个落单的 `mcp.json` 同样不会被认领。布局仍然是未公开的：如果宿主把配置放在别处，插件会找不到服务器并显示空列表。

旧版本插件遗留在 `mcp.json` 旁边的凭据目录会被读取一次并导入 `context.dataDir`，之后不再写入。

### 写入的文件

| 文件 | 内容 |
|---|---|
| `mcp.json` | 只改某个服务器条目的 `Authorization` 头。改写是手术式的：文件其余部分逐字节不变。 |
| `<dataDir>/mcp-credentials/<server>.json` | 凭证：client id、client secret、refresh_token、access_token、scope、过期时间。文件名就是服务器名，限定为 `A-Z a-z 0-9 . _ -` 且不超过 64 个字符，因此 `../../other` 这样的名字无法越出目录。 |
| `<dataDir>/settings.json` | 上面那两个设置。 |
| `<dataDir>/mcp.json.bak` | 每次写入前对 `mcp.json` 的备份。 |
| `<dataDir>/mcp.json.applied.bak` | **确认写入**前对 `mcp.json` 的备份。后台刷新写的是 `mcp.json.bak`，因此永远不会覆盖掉你确认时看到的那份快照。 |

对 `mcp.json` 的写入是原子的：先在同目录写临时文件，再 rename。原始文件权限会被带过去（临时文件默认是默认权限）。写入被串行化，两次写入不会交错。写入失败时临时文件会被删除，原内容保持不变。**备份失败会中止写入**——备份是唯一的退路，所以它先于文件被写入，备份失败就什么都不改。

读取、改写、写入全程在同一把锁内完成，并且锁内会重新读一遍文件，因此并发编辑不会弄丢条目。

### 出网主机

插件只访问两类主机：

1. MCP 配置里列出的 MCP 端点——用于探测和写入后的验活握手。
2. 这些服务器的 OAuth 端点——取自它们的元数据：授权端点、令牌端点、设备授权端点、客户端注册端点、受保护资源文档，以及 `.well-known` 的授权服务器元数据。

除此之外不访问任何主机。没有埋点、没有分析服务、没有第三方服务。

请求前会校验每一个 URL：

- 只允许 `https`（回环地址允许 `http`）；
- URL 里不允许带账号密码；
- 回环地址、RFC 1918（`10/8`、`172.16/12`、`192.168/16`）、运营商级 NAT（`100.64/10`）、链路本地（`169.254/16`）、IPv6 唯一本地（`fc00::/7`）、IPv6 链路本地（`fe80::/10`）、IPv6 组播、未指定地址，以及实例元数据主机，一律拒绝；
- IPv4-mapped、IPv4-compatible 与 NAT64 这几种 IPv6 形态会先还原出里面的 IPv4 地址，因此 `::ffff:127.0.0.1` 和 `::ffff:7f00:1` 同样被拒绝。

重定向是**手动跟随**的，**每一跳都用同一条规则重新检查**——`302` 不能成为绕过守卫的路径。最多跟随 5 跳。

重定向也不能把凭据交给一个本没收到它的主机：

- 跨源重定向**不带** `Authorization` 头、也不带 cookie（`fetch` 自带的行为）；
- `301`、`302`、`303` 会把 `POST` 变成无请求体的 `GET`（浏览器行为）；
- **请求体里装着密钥的请求（令牌请求、动态注册、设备码）一律不跟随重定向** —— 那些接口本来就不该重定向，所以直接拒绝该请求。

这里分两层：**远程服务器**回给你的 URL（元数据文档、令牌端点、设备端点）一律按最严格标准检查，永远够不到内网地址；**你自己配置**的 MCP 端点可以指向内网地址，但前提是打开了「允许内网地址」开关。

### 启动的子进程

| 命令 | 时机 |
|---|---|
| `explorer.exe <authorization-url>`（Windows）、`open <authorization-url>`（macOS）、`xdg-open <authorization-url>`（Linux） | 每次授权一次，用于在默认浏览器打开同意页 |

参数以 argv 数组传入，绝不经过 shell。URL 是依据服务端自己的元数据拼出的授权请求。启动器起不来时，页面会明说，并改为把链接给你复制。

### 状态存放位置

所有持久状态都放在 `context.dataDir`——宿主为这个插件创建的私有目录。除了上面列出的 MCP 配置，不会写到它以外的地方。

### Agent 回合

没有。本包没有声明 `agentAccess`，因此从不让 Agent 跑回合、读文件或调工具；一切都在 Node 进程内或授权服务器自己的页面里完成。

### 读取的会话

没有。本包没有声明 `session.read`，因此看不到任何会话、回合或回复。

### 调用的工具

没有。本包没有声明 `toolAccess`，因此从不调用 MCP 或 Connector 工具。

### 麦克风

没有。本包没有声明 `deviceAccess`，因此从不录音。

### 凭据

令牌本体始终留在 Node 进程里。页面只拿到元信息：scope、过期时间，以及一个八位 SHA-256 指纹，用来分辨两个令牌是否不同。指纹不可逆，也不能当凭据用。凭据不会出现在 HTML、客户端 JavaScript、日志或错误响应中。

内部错误码不会直接显示给用户。服务可能抛出的每一个码都登记在同一份目录里，由目录给出面向用户的文案；没登记的码会立刻失败，而不是漏出去。

## 已知限制

- 只能管理已经在 MCP 配置里的服务器，或通过页面新增的服务器；不会自己发现服务器。
- 需要凭证但没声明 OAuth 的服务器无法从页面登录，只能手工配置请求头。
- 授权码方式的回调地址要手工复制回来（宿主对回环端口有鉴权），除非授权服务器不提供设备码流程，否则优先用设备码。
- 探测只验证握手。服务端可能接受未认证的 `initialize`，却在调用工具时才要令牌。
- 自动续期只在你打开开关后才生效，而且只在 Mini App 运行期间工作。App 停掉期间过期的令牌，会在下一次启动时补刷。

## 开发

本包自带单元测试，在本目录下运行：

```bash
node --test "tests/**/*.test.mjs"
```

覆盖 URL 守卫、凭据路径的目录约束、对 `mcp.json` 的手术式改写，以及一项静态检查：服务可能抛出的每一个错误码都必须已在目录中登记。
